# P6B portfolio canaries and P7A standard tactics

## Status

P6B and P7A deliver a bounded bridge from explaining a checked route to
constructing semantic work through the real MS and Lynx engines. The first
checked execution case is the non-Key synthetic corridor `P.k.D.E`: Chip must
reach and collect a red key, open the red door, and reach the exit.

This is not a full solver or a claim of cross-corpus plan parity. Portfolio
classifications remain proposals, and the execution proof is limited to the
published standard-only Phase-A source.

## P6B: proposal-only portfolio canaries

The closed `p6b-portfolio-canary-suite/v1` contract requires all four plan
relationships:

- one shared plan with different target timing;
- one shared subgoal with different local routes;
- alternative branches with a semantic gameplay-state rejoin and an executed
  common continuation; and
- genuinely different plan proposals.

Each canary binds its exact case/source identity, paired target scope,
dependencies, evidence, confidence, unresolved gaps, and a review state bound
to the complete evidence descriptor. Review can never change the fixed claim
from `proposal / not-proven` to proof.

The two named real cases are CCLP3 level 16, **Two Sets of Rules**, and CCLP1
level 67, **Booster Shots**. Their checked P1B validity and divergent static
comparison records support low-confidence different-plan proposals only. Both
retain a missing-independent-causal-evidence gap.

Standard eligibility is separate from DAT validity. Every eligibility receipt
binds the exact source bytes, its validity evidence, and the explicit CCSolver
source-scope report that excludes the six expanded tile codes `0x70` through
`0x75`. The checked rejoin canary independently executes both branches and
their common continuation in both engines before binding equal canonical
gameplay boundaries, equal semantic fingerprints, and equal terminal gameplay
continuations. It also preserves the observed native distinction: Lynx's
native-exact fingerprints differ after the two branch histories.
The generic schema requires those equal semantic references, truthful
per-target native-fingerprint equality reports, and their dependency links;
independent branch execution remains a producer responsibility. This checked
producer additionally freezes the observed MS-equal/Lynx-different pattern.

## P7A: real-engine tactic realization

P7A implements the first executable standard tactic vocabulary:

- `Reach` an exact coordinate;
- `Collect` one exact source placement and resource amount;
- `Unlock` one exact gate under its typed inventory or remaining-count
  requirement; and
- `WaitUntil` one closed observation predicate using no input.

The evaluator accepts semantic intent plus an existing normalized subgoal
contract. It does not accept a complete replay. It observes a caller-owned
manual run, captures an exact checkpoint, explores deterministic candidates in
restored branches, advances the real engine one tick at a time, checks
invariants after every tick, and disposes every branch and checkpoint.

Search is fail-closed under explicit branch, engine-advance, per-branch tick,
and frontier bounds. Exhaustion returns a stable reason and best observed
boundary; repeating the same bounded attempt must reproduce the diagnostic.
Observation fingerprints are transposition and drift guards, not replay
certificates.

Suffix repair first replays and verifies the complete original successful
witness. The injected sequence must have the same length, preserve every
decision except one non-initial changed decision, and fail when executed in
full. Only the prefix before that decision is retained. The replacement suffix
is evaluated again from an exact prefix checkpoint and is labeled
`replanned-join`.

## Checked review and trust boundary

The checked leaf is:

`ccsolver/fixtures/golden/p7a/phase-a-key-door/`

The unlisted Pages route is:

`/dev/ccsolver/experiments/phase-a/key-door/tactic-realization/`

The leaf contains the portfolio suite, source/eligibility fixture, authentic
standard MS and Lynx artwork, one target realization and fresh-runtime replay
certificate per ruleset, and human HTML/Markdown review. The HTML keeps hashes
and protocol identities out of the primary surface and places failure,
exhaustion, repair, and exact downloads behind progressive disclosure.

`--check` reconstructs the bounded real-engine evidence and byte-compares the
checked leaf. `--attest` and `--emit-dist` validate the exact closed file set,
canonical JSON, manifest lengths and digests, and fixed transaction roots
without running either engine. Pages uses only the engine-free emit path.

No donor replay bytes are read. P1B supplies corpus-wide source identity,
validity, and static comparison evidence; P6A supplies checked Key Pyramid
alignment context for one timing canary. Neither source is treated as an input
stream for P7A construction.

## Deliberate limits

- `PushTo`, device activation, forced traversal, teleports, hazards, and threat
  avoidance remain later tactic work.
- The real corpus canaries are classifications to investigate, not solved
  executions.
- The fresh-runtime certificate is TypeScript engine evidence, not native C
  oracle parity.
- The single Phase-A corridor does not complete the P7 exit gate or justify a
  full-corpus solving sweep.
